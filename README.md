# Project Health Tracker — анализ данных

Сервис для отслеживания здоровья проектов: выявляет задачи с риском
просрочки и считает переработку по часам.

## Этап 3: Анализ данных

На основе синтетических данных (100 задач, 4 проекта) построены графики
и сделаны выводы о состоянии проектов.

### Данные

`data/project_tasks_data.csv` — 100 задач, сгенерированных `src/csv_generate.py`.
Поля: проект, задача, плановые/фактические часы, приоритет, статус,
дедлайн, активность в GitHub (коммиты, открытые issues).

### Метрики

| Метрика | Значение |
|---------|----------|
| Всего задач | 100 |
| Выполнено (Done) | 36.0% |
| В очереди (Todo) | 29.0% |
| Просрочено (Overdue) | 11 |
| Высокий риск (High) | 12 |
| Средняя переработка | 0.22 ч |
| Лидер по коммитам | API Integration |
| Худшая переработка | API Integration |

### Графики

| Файл | Что показывает |

### Выводы

1. **23% задач проблемные** (11 просроченных + 12 с высоким риском).
   Без аналитики пользователь бы их не заметил — это и есть польза сервиса.
2. **API Integration** — лидер по коммитам, но и худший по суммарной
   переработке. Активность ≠ укладывание в сроки.
3. **Распределение статусов** близко к равномерному (36/29/35) — это
   ограничение синтетических данных; на реальных данных ожидается
   перекос в сторону Done.
4. **Средняя переработка мала (0.22 ч)** — артефакт генератора
   (факт = план × 0.7–1.5). На реальных данных разброс был бы выше.
